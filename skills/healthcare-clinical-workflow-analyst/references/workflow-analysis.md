# Workflow Analysis Reference

Use when the task requires workflow discovery, AS-IS/TO-BE analysis, process redesign, or implementation workflow assessment.

## Analyze the whole work system

Consider:

- people;
- tasks;
- technology;
- information;
- physical environment;
- communication;
- policy;
- exceptions;
- timing;
- dependencies.

## AS-IS

Capture the real current process, including workarounds and informal communication.

Do not document only the intended policy workflow.

## TO-BE

Design the future workflow only after the problem and current workflow are understood.

Identify:

- what is removed;
- what remains manual;
- what becomes automated;
- what requires human verification;
- what changes ownership;
- what new dependencies are created;
- what happens on failure.

## Workflow step model

Use as needed:

**Trigger → Actor → Action → System/Device → Information → Decision → Handoff → Exception → Outcome**

## Key questions

- What starts the process?
- Who owns each step?
- Where are handoffs?
- What information is needed?
- What creates delay?
- Where is duplicate work?
- Where can users bypass the intended process?
- What happens when technology is unavailable?
- How is work reconciled after recovery?
